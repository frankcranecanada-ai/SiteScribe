Two-line B05 secondary and activity rows in portrait on a phone

REPORTED PROBLEM
----------------
On the main Working Memory screen, a phone held in portrait did not leave enough room for the
secondary record description. The operator asked whether to move the data onto a second line or
to remove the total hours, and for a recommendation. The problem is portrait-only; landscape has
room.

MEASUREMENT
-----------
Measured live at 375px portrait, on a secondary row titled
"Teams meeting MDS/WECC -Eddy, work on minutes. meeting at 11:30 and 15:30":

  row width                                342px
  left icons (grip, deliverable, dot)       36px
  right cluster (date + hours + OPEN)      168px
  description                              106px

The metadata occupied 58% more of the row than the text it described, and titles truncated after
about three words.

RECOMMENDATION TAKEN
--------------------
Two lines, not removing the hours badge. Removing hours would have returned only about 70px,
leaving the description at roughly 176px - still under half the row - and would have discarded the
billing figure the v0.8.11 H:MM work had just improved. Moving the metadata to its own line gives
the description the full row width.

CHANGES
-------
styles.css only. One media block appended at the end of the stylesheet:

  @media (max-width: 640px) and (orientation: portrait) {
    .secondary-record-line { grid-template-columns: auto minmax(0, 1fr); row-gap: 3px; ... }
    .secondary-record-line .record-right { grid-column: 2; justify-content: flex-start;
                                           width: 100%; min-width: 0; }
    .secondary-record-line .record-inline-meta { max-width: none; }
  }

The row is a three-column grid (auto / title / right). Dropping it to two columns and assigning
the right cluster to column 2 places that cluster on a second line, indented under the title
rather than under the drag grip.

The block is deliberately placed at the end of the stylesheet. Several earlier
@media (max-width: 640px) rules set the same grid-template-columns and .record-right properties;
at equal specificity the later rule wins. Placed earlier in the file the rule had no effect, which
was caught during browser verification.

Activity rows carry the secondary-record-line class as well, so they get the same treatment. This
is intended: they are the same visual family in B05.

RESULT

  landscape 812x375  one line    description 466px            row height 33px (unchanged)
  desktop 1200x900   one line    description 829px            row height 33px (unchanged)
