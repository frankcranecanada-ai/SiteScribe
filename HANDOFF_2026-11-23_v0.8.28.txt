3. MOST RECENT REQUESTS AND COMPLETED WORK (v0.8.28)

The user requested a thorough iPhone display review, then explicitly directed:
- Fix landscape Expense editors whose controls/Save were off-screen.
- Make touch targets larger without making the display busy.
- Change the mobile record popup to a full-screen editor.

Diagnosis:
- The old time editor had five fixed columns plus an auto sixth Expense column.
  Expense added roughly 340 px and widened the entire detail card. Save,
  Currency, Expense Type and Add Activity could move off-screen in landscape.
- The detail card allowed vertical touch panning only, limiting pinch gestures.
- The empty invisible toast notification could intercept a lower-right OPEN tap.

Implemented:
- Expense fields now occupy a bounded, separate grid row. No implicit sixth
  column; time/expense grids cannot widen the detail card.
- Touch OPEN/COPY boxes are at least 44 x 36 CSS px; their visible oval faces
  stay 22 px high. Grips are 28 x 32; branch toggles are 32 x 32. Actual boxes
  reserve space instead of invisible overlapping hit areas. Primary mobile
  date/COPY/OPEN visuals remain at the end of the second description line.
- Touch configuration and saved-site/Dropbox row buttons have 32 px minimum
  touch heights. Report filter labels have more vertical touch room.
- At touch viewport widths up to 1024 px, primary, secondary and activity
  editors fill the screen. A sticky header keeps Back reachable while scrolling.
- Mobile detail uses touch-action: pan-y pinch-zoom. The viewport meta tag does
  not disable user scaling. Desktop retains its popup and Close label.
- Back reuses the existing explicit-close/commit handler. This is a responsive
  full-screen presentation, not a new URL/router or browser-history screen.
  Do not promise that Back saves a genuinely new, not-yet-added record.
- Non-interactive toast messages are click-through, visible or hidden.

App files changed: styles.css, index.html and version strings in app.js.
app.js otherwise matches v0.8.27. No storage, record, import, Dropbox, parser,
report/PDF, drag-handler or data-schema logic was changed by this release.
The new candidate, regression/browser tests and evidence are checked into Git.

5. RECENT FEATURES TO PRESERVE

- Primary -> Secondary -> Activity is a strictly capped three-level tree.
- B05 primary/secondary row bodies toggle their children. Explicit OPEN pills
  open the chosen editor; activity rows open their own activity.
- Grip-based drag/move/reorder uses destination highlighting/insertion lines.
  A secondary can become an activity under another secondary; an activity can
  be promoted back to a secondary. Locks and fourth-level guards apply.
- Secondary titles with activities are lightly bold; activity descriptions are
  italic. Report selection and output preserve hierarchy/indentation/emphasis,
  including parent context when only children are selected.
- Copy Record includes the primary, secondaries and indented activities.
- Primary title editing is inside the opened primary record, with Save/Cancel.
- New secondary/activity billing defaults to REG. Existing values are preserved.
- Work Date uses a stored work date, falling back to record creation when absent.
  Opening an older entry must not stamp today's date into it. New entries can
  default to today. Start/End take typed 24-hour text; hours display HH:MM while
  stored hours remain decimal and direct-only.
- The old fixed Email footer was removed because it blocked iPhone Save.
  Email Current Memory/status are in B01. Do not restore a blocking footer.
- UPDATE DROPBOX SITE FILE has a green outline. Stable-file update and dated
  backup copy are separate operations. Brief hover help replaces the long
  instructional paragraph. B02 saved-site rows remain compact.
- Dropbox listing ignores le-initial-sms-receipts-v1.json, an LE flag file, but
  retains legitimate SiteScribe JSONs and genuine unrecognized-file diagnostics.
- Email PDF generates a real linked PDF directly (no print-to-PDF step).
  Dropbox links remain clickable. Desktop follows the LE-style download plus
  email-draft handoff; attachment remains a deliberate user action. Supported
  mobile browsers can share the PDF. No automatic email sending occurs.
